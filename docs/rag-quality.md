# Качество поиска по руководствам

## Задача

Ответ на вопрос механика должен опираться на конкретную страницу руководства по его
двигателю, а не на общие знания модели. Значит, поиск обязан:

1. не выдавать документы чужого двигателя — иначе агент процитирует норматив от другой
   модели;
2. находить страницу с нужным нормативом (момент затяжки, зазор, давление) в топ-3,
   потому что агент получает 6 фрагментов и ссылается на них;
3. возвращать номер страницы PDF, которого достаточно, чтобы открыть документ и проверить.

## Как устроен индекс

| Шаг | Реализация |
|---|---|
| Извлечение | PyMuPDF, текст постранично |
| Очистка | удаление повторяющихся колонтитулов, склейка переносов |
| Чанкование | по границам страниц, ~700 символов, максимум 1100, с перекрытием |
| Метаданные | `doc_id`, `manual_ref`, `pdf_page` (номер страницы PDF, не печатный) |
| Индекс | BM25Okapi по стеммированным токенам (Snowball, русский) |
| Фильтр | жёсткий: чанк допускается только если его документ относится к модели двигателя |

## Контрольный набор

12 вопросов в `backend/eval/questions.jsonl`: по три на каждый двигатель, формулировки
как у механика («с каким моментом затягивать…»), ожидаемые страницы выписаны вручную
по PDF. Для каждого вопроса допускается несколько правильных страниц — в руководстве
норматив часто дублируется в таблице и в тексте.

Прогон:

```bash
python backend/scripts/eval_rag.py
```

Метрики: hit@1 и hit@3 (правильная страница в первой / первой тройке выдачи), MRR.

## Разбор промаха

`змз409-clearance`: «нужно ли регулировать тепловые зазоры клапанов».

Правильные страницы — p43 (гидрокомпенсаторы: регулировка не требуется) и p19.
Поиск выдал p175 (зазор поршневого кольца) и p130 (тепловые зазоры в другом контексте).

Причина в лексике: в вопросе есть «тепловые зазоры», и этого достаточно, чтобы
BM25 поднял страницу с таблицей зазоров, где слово «тепловые» встречается чаще, чем
на странице про гидрокомпенсаторы, где ответ — отрицание («регулировка не требуется»).
Ответ есть в документе, но на странице, где слов из вопроса меньше.

Косвенно это подтверждается поведением агента: на этот вопрос он находит страницу p43
вторым запросом («гидрокомпенсаторы»), потому что у него есть второй шанс
переформулировать. Поиск с одним запросом промахивается, агент — нет.

## Что даёт гибридный поиск (BM25 + эмбеддинги)

Проверялся вариант с `baai/bge-m3` (1024-мерные эмбеддинги через ProxyAPI) и
нормированной суммой `(1-w)·BM25 + w·cos`. Эмбеддинги считались по всем 3523 чанкам
один раз, метрики — на том же наборе вопросов и с теми же правилами (фильтр по
двигателю, не больше двух чанков с одной страницы):

| Вес эмбеддингов | hit@1 | hit@3 | MRR | Промахи |
|---|---|---|---|---|
| 0.0 (только BM25) | 83 % | 92 % | 0.88 | zmz409-clearance |
| 0.3 | 83 % | 92 % | 0.88 | zmz409-clearance |
| 0.5 | 67 % | 92 % | 0.79 | zmz409-clearance |
| 0.7 | 67 % | 83 % | 0.77 | zmz409-clearance |
| 1.0 (только эмбеддинги) | 67 % | 83 % | 0.75 | zmz409-clearance, yamz236-rocker-torque |

**Решение: остаёмся на BM25.** Гибрид не улучшает ни одну метрику, а при весе ≥ 0.5
заметно ухудшает: эмбеддинги поднимают страницы «по смыслу» (зазоры вообще), вытесняя
страницы с точным нормативом. При весе 1.0 теряется даже вопрос про моменты затяжки
осей коромысел — модель находит страницы про коромысла (РК стр. 43, 286, 41), но не ту,
где числа.

Причина в характере запросов: механик спрашивает «с каким моментом затягивать болты
осей коромысел», и правильный ответ — страница, где встречаются и «момент», и «оси
коромысел», и «кгс·м». Для таких запросов лексика точнее семантики, а общая модель
эмбеддингов плохо различает страницы с одинаковой терминологией и разными числами.

Побочный аргумент: эмбеддинги на индексации добавляют ~10 минут и внешнюю зависимость
на старте контейнера (при 429 от API — с повторами), а на запросе — сетевой вызов перед
поиском. За ноль прибавки к качеству это не окупается.

Промах `zmz409-clearance` остаётся, но закрывается вторым запросом агента: инструмент
`search_manuals` можно вызывать несколько раз с разными формулировками, и в реальном
диалоге агент находит страницу про гидрокомпенсаторы сам.


## Ограничения

- Набор из 12 вопросов — не бенчмарк: он показывает, что основные нормативы находятся,
  а не покрывает все формулировки.
- PDF содержат сканы таблиц; часть страниц извлечена без табличной структуры, поэтому
  числа могут соседствовать с подписями столбцов. Агент в таких случаях опирается на
  текст страницы и не пересчитывает значения.
- Оценка считается по наличию правильной страницы в выдаче, а не по качеству
  финального ответа. Качество ответа проверялось отдельно, вручную, по сценариям
  из README.
